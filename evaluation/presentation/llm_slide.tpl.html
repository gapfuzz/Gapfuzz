3. 중간 결과 ⑤ Claude 연동

고칠 곳을 Claude가 코드로 옮기고, gapfuzz가 검사합니다

사람이 하네스를 고쳐 쓰던 단계에 Claude API를 연결했습니다. LLM이 틀린 코드를 내도 검증과 크래시 귀속이 걸러 냅니다.

자동 수정 흐름 gapfuzz llmfix, 제안 하나마다

gapfuzz

고칠 곳 하네스 코드, 제안 문장, 막힌 라이브러리 분기, 지킬 규칙을 묶어 보냄

Claude

수정 코드 고친 하네스 전체와 바꾼 줄마다 이유 주석

gapfuzz

검사 컴파일 → 60초 × 2회 퍼징 → 겨냥한 분기가 열렸나 → 크래시는 누구 탓인가

통과

diff와 보고서를 남기고 사람이 읽고 넣음

실패

컴파일 오류, 아직 막힌 분기, “하네스 버그” 판정 근거를 같은 대화로 돌려줌 (최대 3번)

// Claude가 zlib 하네스에 넣은 코드 (제안: inflate를 직접 안 부름)
int flush = kFlushModes[data[0] % 5];   // [gapfuzz-llm] 입력으로 flush 선택
int ret = inflate(&strm, flush);       // → 막힌 분기 7개 모두 열림

라이브러리 7개의 고칠 곳 전체를 맡긴 결과

@@OPEN@@

@@HUMAN@@

왜 믿을 수 있나

LLM 출력은 그대로 쓰지 않습니다. 열렸는지는 실제 퍼징으로 재고, 크래시는 귀속 규칙이 하네스 탓인지 가립니다. @@FILTER@@

하네스 코드는 외부로 나갑니다

Claude API를 쓰므로 하네스와 라이브러리 일부 코드가 Anthropic으로 전송됩니다. 공개 오픈소스라 문제없지만, 비공개 코드라면 로컬 모델로 바꿔 끼울 수 있게 호출 부분을 분리해 두었습니다.

50초. 마지막 결과는 이번 주에 붙인 기능입니다. 도구가 고칠 곳을 알려 주면 사람이 하네스를 고쳐 쓰던 단계를 Claude API에 맡겼습니다. 도구가 하네스와 제안, 막힌 분기의 코드를 보내면 Claude가 고친 하네스를 돌려주고, 도구가 컴파일하고 퍼징해서 노린 분기가 열렸는지, 크래시는 누구 탓인지 검사합니다. 실패하면 이유를 돌려주고 다시 고치게 합니다. @@SCRIPT@@ 중요한 건 LLM을 믿는 게 아니라 검사한다는 점입니다.
