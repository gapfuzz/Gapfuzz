# 하네스 전체 기준 실험 — yyjson

라이브러리의 하네스를 모두 따로 돌린 뒤 묶음별로 커버리지를 합쳐서 비교합니다.
하네스마다 86400초씩, 같은 회차는 같은 시드. 값은 중앙값 [최솟값–최댓값].

- **A 기준**: OSS-Fuzz 하네스 전체. 하네스 3개 × 86400초 = 회차당 CPU 72.0시간 (official, official_patch, official_merge_patch)
- **B 수정**: 고친 버전이 있는 하네스는 고친 것으로 바꿈 (하네스 수는 A와 같음). 하네스 3개 × 86400초 = 회차당 CPU 72.0시간 (official_llm, official_patch_llm, official_merge_patch)
- **C 수정 + gapfuzz_ops**: B + gapfuzz_ops. 하네스 4개 × 86400초 = 회차당 CPU 96.0시간 (official_llm, official_patch_llm, official_merge_patch, gapfuzz_ops)
- **C 동일 계산량**: C와 같은 하네스, 총 퍼징 시간을 B와 맞춤. 하네스 4개 × 64800초 = 회차당 CPU 72.0시간

gapfuzz_ops 생성 상태: COMPLETE · API 10/10 · 검사 퍼징 크래시 0

| 묶음 | 회차 | 회차당 CPU 시간 | 라인 | 분기 | 어느 하네스도 안 부르는 API |
|---|---:|---:|---|---|---:|
| A 기준 | 1 | 72.0 | 47.68% [47.68–47.68] | 52.27% [52.27–52.27] | 327 / 405 |
| B 수정 | 1 | 72.0 | 48.49% [48.49–48.49] | 54.27% [54.27–54.27] | 327 / 405 |
| C 수정 + gapfuzz_ops | 1 | 96.0 | 64.56% [64.56–64.56] | 65.52% [65.52–65.52] | 284 / 405 |
| C 동일 계산량 | 1 | 72.0 | 64.56% [64.56–64.56] | 65.52% [65.52–65.52] | 284 / 405 |

## 회차별 차이

같은 회차끼리(같은 시드, 같은 컴퓨터) 뒤 묶음에서 앞 묶음을 뺀 값입니다. p는 Wilcoxon 부호순위 검정(양측, 정확).
고치지 않은 하네스는 묶음들이 같은 실행 기록을 같이 쓰므로, 독립 표본 검정이 아니라 회차별 대응 비교를 씁니다.

| 비교 | 회차 | 분기 커버리지 차이 | 오른 회차 | p | 안 부르는 API 수 차이 | 뜻 |
|---|---:|---|---:|---:|---:|---|
| A → B | 1 | +2.01%p [+2.01 – +2.01] | 1/1 | 1 | 0 | 기존 하네스를 고친 효과 (하네스 수와 총 시간이 같음) |
| B → C | 1 | +11.25%p [+11.25 – +11.25] | 1/1 | 1 | -43 | gapfuzz_ops를 하나 더 돌린 효과 (C가 하네스 1개만큼 시간을 더 씀) |
| B → C 동일 계산량 | 1 | +11.25%p [+11.25 – +11.25] | 1/1 | 1 | -43 | 같은 총 시간에서 gapfuzz_ops를 넣은 효과 |
| A → C | 1 | +13.25%p [+13.25 – +13.25] | 1/1 | 1 | -43 | 전체 효과 |

회차가 1회뿐이라 p값으로는 판단할 수 없습니다(6회 미만이면 모든 회차가 올라도 p가 0.05보다 큽니다). 차이의 크기와 방향만 보세요.

동일 계산량: C의 하네스 4개를 각각 64800초 시점에서 끊어 합쳤습니다 (4 × 64800초 ≈ B의 3 × 86400초). 퍼징을 다시 돌리지 않고, 실행 중 그 시각에 찍어 둔 코퍼스로 쟀습니다.

## 시간에 따른 커버리지

하네스마다 그 시각까지 퍼징한 코퍼스로 잰 값을 묶음별로 합쳤습니다. 칸은 `분기 커버리지 · 어느 하네스도 안 부르는 API 수` (중앙값).
고친 하네스가 없는 묶음은 앞 묶음과 같은 값입니다.
